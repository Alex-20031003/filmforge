# Employees demo seed

Из каталога `backend`:

```powershell
pnpm prisma:seed
```

Сидер использует существующие `SEED_TEMP_PASSWORD` и `OWNER_RECOVERY_EMAIL`
из локального `.env`. Пароль не записывается в исходники и не выводится в лог.

Он сохраняет начальный аккаунт `alex.morgan` и добавляет 32 демо-сотрудника:

- 1 OWNER, 2 ADMIN, 29 MEMBER;
- 28 ACTIVE, 2 ON_LEAVE, 2 INACTIVE;
- все 15 отделов.

Если до запуска был только начальный ACTIVE сотрудник, после запуска будет
33 профиля. Обычный каталог вернёт 31 сотрудника: 29 ACTIVE и 2 ON_LEAVE.
При `limit=20` это две страницы: 20 и 11 записей. INACTIVE в каталог не попадают.

## Аккаунты и активация

Статус сотрудника и статус аккаунта — разные поля. По явному запросу
пользователя новые ACTIVE демо-сотрудники получают аккаунты ACTIVE с
`mustChangePassword=false`: можно войти сразу, без подтверждения почты.
ON_LEAVE/INACTIVE получают DISABLED аккаунты. Сидер не создаёт сессии
и не отправляет письма: сессия создаётся обычным login после проверки пароля.

Это исключение для локальных демо-данных. Правила обычной активации
в приложении и создание начального `alex.morgan` не изменены.

Для проверки прав можно войти под следующими аккаунтами:

| Username        | Роль   | Назначение                                         |
| --------------- | ------ | -------------------------------------------------- |
| `clara.hayes`   | OWNER  | Второй владелец, защита последнего OWNER           |
| `emma.turner`   | ADMIN  | Редактирование служебных полей и ограничения ADMIN |
| `oliver.reed`   | ADMIN  | Дополнительный ADMIN                               |
| `anna.mueller`  | MEMBER | Свой профиль и запрет изменения служебных полей    |
| `james.bennett` | MEMBER | Другой сотрудник для проверки прав                 |

Пароль новых демо-аккаунтов — значение `SEED_TEMP_PASSWORD`, заданное
при первом запуске. Если затем изменить пароль через API, сидер его не сбросит.

По умолчанию адреса имеют вид `anna.mueller@northlight.example.test`.
Это фиктивные уникальные адреса; для входа доступ к ним не нужен.
`recoveryEmailVerifiedAt` остаётся `null`: почта не считается подтверждённой,
поэтому forgot-password для этих аккаунтов не отправляет письмо.
Почтовые сценарии проверяются отдельно на обычном PENDING_ACTIVATION
аккаунте с доступным адресом и полным подтверждением. Контролируемый домен
можно задать через `SEED_EMPLOYEE_EMAIL_DOMAIN` до создания аккаунтов;
этот demo seed почту не верифицирует.

## Повторный запуск

Сидер ищет аккаунты по username и использует `upsert` с пустым `update`.
Повторный запуск не создаёт дубликаты и не сбрасывает пароль, активацию,
статусы, профиль или сессии существующих аккаунтов. Изменение seed-данных,
домена или временного пароля применяется только к новым аккаунтам.

Если найденный username принадлежит другой компании или не имеет профиля,
сидер завершится ошибкой. Данные не удаляются. При частичном выполнении
повторный запуск добавит недостающие записи.

## Ручная проверка

1. Запусти сидер дважды: количество сотрудников должно остаться тем же.
2. С действующей сессией проверь `GET /api/v1/employees?page=1&limit=20`,
   затем `page=2`: `meta.total` одинаковый, профили страниц не повторяются.
3. Проверь `search=anna`, `search=Producer`, `department=ACTING` и
   `status=ON_LEAVE`: `meta.total` считает только подходящих сотрудников.
4. Поиск по отсутствующей строке должен вернуть пустой `data`,
   `total=0` и `totalPages=0`.
5. Войди под OWNER/ADMIN/MEMBER демо-аккаунтами и проверь разрешённые
   и запрещённые PATCH-запросы в отдельных сессиях. Новый `clara.hayes`
   уже является ACTIVE OWNER и учитывается в проверке последнего владельца.

Текущий seed ограничен Employees. Другие модели и полный набор 200–250
сотрудников относятся к последующему наполнению портфолио.
